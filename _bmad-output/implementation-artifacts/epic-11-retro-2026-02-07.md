## What Went Well

### 1. Consistent Architecture Across 12 Stories
Every story followed the same pattern: FormRequest → Controller → Resource (backend) and Service → Composable → Component (frontend). No architectural drift across the entire epic despite its size.

### 2. Code Review Process Catching Real Bugs
The adversarial code review process proved its value by catching critical issues:
- **N+1 queries** (11-5) — would have caused production performance issues
- **LIKE injection vulnerability** (11-5, 11-9) — actual SQL security risk
- **Race conditions** (11-5) — stale API responses arriving after newer ones
- **Missing tests marked as done** (11-8) — process accountability gap
- **Timezone-naive deadline comparison** (11-7) — logic bug in CTA display

### 3. Reusable Component Design
- `RegistrationCta.vue` — one component, two variants, used across 4 locations
- `LockedContentTeaser.vue` — reusable locked-content pattern
- `Pagination` component — shared across faces and missions lists
- `apiClient.ts` — shared axios instance eliminating duplication
- `PerspectiveToggle.vue` — accessible toggle with keyboard navigation

### 4. Epic 10 Preparation Paid Off
The header (11-0a) and footer (11-0b) stories recommended in the Epic 10 retrospective became the backbone of every public page. Forward planning at its best.

### 5. SEO & Slug Implementation
Clean slug generation with collision handling (`-2`, `-3` suffixes), database migration with backfill of existing records, and zero breaking changes to existing functionality.

### 6. Accessibility Consistency
Every story included: aria-labels, focus-visible states, keyboard navigation, `prefers-reduced-motion` support (11-2), aria-hidden on decorative elements, and screen-reader-friendly content.

### 7. Design System Establishment
Created `design-system.md` in 11-0a with WEACT brand colors (#198496 teal), typography, and spacing patterns. All subsequent stories referenced this for visual consistency.

## What Could Be Improved

### 1. Gemini MCP Availability
Stories 11-1 and 11-7 hit **503 errors** from Gemini MCP for design generation. Fallback to manual creation using design-system.md worked but required more effort. External tooling dependencies are a risk.

### 2. False Task Completion Markers (CRITICAL)
In Story 11-8, Task 2.2 (PublicMissionsView CTA tests) was marked `[x]` but the tests didn't exist and the file wasn't even in the git changeset. The code review caught it, but this is a process gap — tasks should be verified before marking complete.

### 3. Carried-Forward Items Keep Sliding
The ESLint unused imports rule and email change story have been carried forward through **Epic 9 → 10 → 11** (three epics) without resolution. This is a pattern of chronic deferral.

### 4. Mock Data on Landing Page
Story 11-1 uses hardcoded mock mission data for the "Missions en cours" section. This was flagged in code review but deferred. It's technical debt that creates a gap between what visitors see and actual platform data.

### 5. Test Discovery Gaps Before Review
Several code reviews found issues that should have been caught earlier:
- 11-5: N+1 queries had no performance-related tests
- 11-6: Producer avatar missing `loading="lazy"` attribute
- 11-8: Entire PublicMissionsView CTA test file was missing
- Pattern: Dev marks tasks complete → code review finds gaps → rework required

### 6. No Component Documentation
30+ components created with no Storybook or usage documentation. As the component library grows, this becomes a maintenance and onboarding burden.
